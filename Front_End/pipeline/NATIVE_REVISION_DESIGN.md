# Native-source revision: implemented boundary, real revision acceptance pending

The host now classifies actual inputs through `native_revision.py` before dispatch. The original `native.py`, `readers.py`, frozen references and deterministic acceptance exceptions remain unchanged. This is a limited explicit new-version route; no real changed-year native source has yet completed independent full admission.

## Routing and authority

Exact complete pinned files use the deterministic adapter. A complete same-structure bundle with changed bytes creates an immutable host `NativeRevision` receipt. It records the original logical source, frozen profile/reference hashes, complete resource roles, actual input hashes, changed resources and dispatch implementation hashes. A model-supplied source contract cannot manufacture this authority.

Incomplete, mixed, duplicate-role or recognizably changed-layout native bundles pause with their concrete diagnostic. Unknown unrelated data uses ordinary autonomy. Mutation after upload remains a failure rather than a source revision.

The boundary is checked again after archive extraction and before proposing or executing a contract. Extracted containers cannot hide a native source behind a new autonomous alias. Exact pinned archives currently require the original files uploaded individually. Extracted Excel members stored under generated `.input` filenames likewise require original individual uploads because the frozen Excel reader refuses that storage extension. This limitation is explicit, not a generic fallback.

The host passes its receipt directly to trusted QA. QA re-derives it from the actual files and permits only that reserved logical source ID. The receipt enters admission evidence and the semantic fingerprint without task-specific identifiers. A new immutable adapter version records code, contract, sandbox image and trusted implementation hashes.

## First supported transition

A revision must be an evidenced full snapshot with coverage at least as wide as both the frozen baseline and the current published version. Every original required resource must be declared with its correct grain. Official publisher and jurisdiction evidence must match. Sample QA, full execution and independent full QA still apply; the old exception sets grant no exemption.

NSW and QLD same-structure full snapshots can enter this investigation. VIC's required node lookup currently has no independently validated canonical-v2 lookup grain, so VIC revisions pause explicitly. The four-file requirement cannot be relaxed, and node rows cannot be discarded or converted into synthetic observations. Native partition/incremental composition also pauses pending a dedicated verified transition; a single new-year file cannot silently erase prior history.

Publication preserves `official_nsw`, `official_vic` or `official_qld`, so website source replacement uses the same logical identity. A transaction atomically switches that source's batch while retaining every other source and historical release. A failed transition leaves the current release available.

## Verification and remaining acceptance

Synthetic tests cover immutable host receipts; exact pinned routing; complete hash drift; missing roles; changed headers; upload mutation; forged reserved identities; narrower coverage; forbidden partitions; the VIC lookup limitation; added public evidence; and native archives, including pinned and incomplete bundles. They do not claim successful admission of an actual new-year dataset.

The existing original three-state full-volume regression remains a separate baseline check. Before claiming real native revision acceptance, run a complete actual official changed-byte snapshot through source investigation, sample/full sandbox execution, independent strict QA, PostgreSQL reconciliation and the website. Confirm same-source replacement, no-change replay and preservation of the preceding release. An unrelated new-source or synthetic transition is not equivalent evidence.
