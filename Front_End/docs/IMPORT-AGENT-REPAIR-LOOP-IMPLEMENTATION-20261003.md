## 1. 本轮目标和取舍

让现有数据 Agent 能在受控工作区中，依据宿主返回的具体诊断，自主修订来源合同、字段映射、证据引用和 Python adapter，重新接受同一套独立 QA。候选错误可以进入修订循环；系统故障、权限越界、无法确认的关键语义和预算耗尽不能被模型自行豁免。

本轮放宽的是“遇到候选错误即停止整轮开发／不准启动 Agent”的流程限制。数据准确性、证据适用范围、独立 QA、删除授权、隔离边界和发布原子性不放宽。

交付应回答三个问题：

1. 宿主能否正确区分“当前候选写错”与“系统没有实现所需能力”？
2. Agent 能否用现有工具自主修复前一种问题，随后重新通过独立检查？
3. 新建 WA 隔离任务能否完成上传、样本执行与 QA、全量执行与 QA、注册、发布、查询及两次重传 `no_change`？

成功标准是上述行为和证据，不是增加测试总数或修改更多代码。WA 已是开发用例，其成功不能称为未见来源盲测成功，也不能证明所有州、格式或数据粒度均已支持。

## 4. D1：把错误交回正确的处理方

### 4.1 分类策略

复用 `capability_preflight.py` 的 blocker 结构与现有异常，不先新增数据库状态或通用策略框架。可以加兼容字段表达处理方式；必须保持旧消费者可读取原 `code`、`kind`、`details`。

| 情况 | 本轮处理 | 继续的必要条件 |
| --- | --- | --- |
| 候选选择不兼容，但宿主已有可满足用户意图的操作 | 返回 Agent 修订；当前候选仍失败 | 修订后通过原门禁；不能凭建议直接准入 |
| 错误字段、错误引用、adapter 代码错误、可定位的映射错误 | 返回 Agent 读取诊断并修订 | 原行重放、字段语义和 QA 不变 |
| 缺少证据或适用范围冲突 | Agent 用现有工具调查 | 证据真实且适用；无法确定关键语义则 `needs_input` |
| 原始数据矛盾／业务键无法确定 | 允许调查解释，不允许猜测或悄悄删行 | 有可靠解释或补充资料；否则保存阻塞 |
| 缺失可信执行依赖、损坏收据、宿主内部故障、未实现且无安全替代的算子 | 系统阻塞 | 停止数据模型修补尝试，保存完整定位 |
| 沙箱越界、绕过 QA、删除权限不足且无符合意图的替代方案 | 拒绝相关操作 | 不允许模型自签权限；必要时明确询问用户意图 |
| 取消、预算耗尽、已确认无进展 | 按现有机制停止 | 不转成普通可重试错误，不重置累计预算 |

不能由模型、上传文档或 adapter 返回的文本决定自己属于“小兼容问题”。宿主根据可信错误出处和已验证能力产生分类。未知异常不能默认为可自动放行；保留诊断并按现有保守故障路径处理。

### 4.3 当前更新冲突如何处理

对于经过验证的 bounded response，如果没有删除授权：

1. 保留 `completeness=bounded_response_only` 和 `deletion_authority=false`。
2. 明确当前 `partition` 不被允许。说明宿主已有 incremental 路径及其条件，不能宣称其余字段、范围、源身份和 QA 都已通过。

5. 修订后重新运行完整预检。输入绑定、时间范围、键、独立 QA、合并和发布检查照常执行。

## 5. D2：让现有 Agent 完成修订，而不是让开发助手代劳

### 5.1 复用现有执行链

在当前配置下核实 `agent_process → AgentSession → Codex TaskBridge／legacy tools` 的实际链路。当前 `autonomous_adaptation_v1` 为宿主控制的 opt-in；如果本轮需要启用，只在新隔离 runtime 中明确设布尔值 true，并记录 session 快照。不得修改普通网站或默认配置，上传参数也不能开启它。

模型选择及推理强度使用现有有效路由配置并记录实际值。本轮不升级模型、增大现有 model/tool/correction 配额，也不新建数据 Agent。脚本假模型的工具序列不能算真实自主导入。

受控闭环为：

```text
候选提交 → 宿主预检／QA
             ├─ 候选可修订 → 返回具体诊断 → Agent 读取证据／修改候选
             │                                ↓
             │                         重新提交并重新检查
             ├─ 关键证据无法解决 → 保存 needs_input
             ├─ 系统／隔离故障 → 保存阻塞并停止
             └─ 所有必需门禁通过 → 注册与原子发布
```

图中的“可修订”只代表可以继续工作，不代表当前数据可以执行或发布。样本通过不替代全量通过。

### 5.2 允许 AI 做什么

- 读取任务范围内的原数据剖析、官方证据、完整错误与 SDK。
- 提议或修订字段、日期／时区、坐标、来源资源和更新方式声明；所有语义仍需验证。
- 在既有工作区编辑 adapter Python、编写局部诊断程序，调用现有隔离执行工具。
- 修正候选对现有能力的调用，进行样本修订后再全量验证。

AI 不可修改宿主 QA／策略文件、原始上传、独立验收预期、主库、发布授权或运行安全配置。不得动态安装未审查依赖；不得用任意 Python 输出替代尚未支持的语义算子与独立验证器。需要的变换超出现有操作集合时，应报告真实能力缺口，而非写一段看似正确但无法独立复核的代码。

### 5.3 失效、恢复与进展

- 候选合同或执行代码改变后，按现有机制使旧 sample/full admission、registered/ready 等不适用状态失效。必须用新候选身份完成要求的检查，不能复用旧成功标签。
- 保留各次候选、修订原因、失败检查和完整工具结果。不能删除旧报错，让最终报告只剩成功。
- 进展以宿主确认的特定问题解决、相关检查通过或真实新证据为依据；只改合同哈希、链接、措辞、文件名和重复下载不得重置预算。
- 复用现有“警告／更换调查方式／停止”机制。同一未解决问题不能被其他无关检查的成功掩盖。
- 不因为产生一次新的失败就结束开发轮次，也不因为“AI 还在思考”允许无限继续。取消、系统阻塞及累计上限优先。
- 两条运行入口均须验证取消和 BudgetExhausted 不被包装成普通 evidence-needed 后继续调用模型。

## 6. D3：增量更新必须证明保留了什么

不重写 `publication.py` 的增量算法。先读现有实现及 `test_bounded_publication.py`、`test_update_compatibility.py`、`test_publication_identity.py`、`test_publication_idempotency.py`；只有与本轮新路径直接相关的确认缺陷才做最小修正。

在小型、确定性的隔离用例中构造非空基线，验证：

- 首次 bounded incremental 没有历史 batch 也能进入既有发布路径；不虚称是完整月份或全量来源。
- 存在基线时，上传内新键可新增；相同业务键的更新必须满足现有身份、范围和操作约束。
- 上传未出现的旧记录不能因“本批没有”被删除。区间外记录保持，子表的缺席也不能被当作删除指令。
- 窗口内外同键冲突按照现有 bounded 约束被拒绝，release 保持不变；不能借更新模式规避范围授权。
- 受限子集不能执行 partition/snapshot 删除；改字段名称或错误码不改变该结论。
- 相同有效内容重传及只改文件名返回 `no_change`；batch/release 不漂移，执行身份可以不同。

验收 oracle 必须独立声明预期的键、字段与保留记录，不能把 adapter 输出复制为期望值。对失败检查应继续尝试受控注册／发布并确认被拒绝，而不只检查错误字符串。

## 9. 本轮允许继续的边界和停止条件

以下情况可以在本轮继续：

- 数据 Agent 在同一 job、同一预算内处理可修订候选问题，重新走检查。
- 冻结前修复本轮 D1–D3 的具体缺口并做定向回归。
- 验收脚本的纯参数／路径／结果读取错误，可最多修复两个独立根因；保留首个失败，在总时限内先无模型验证。不能降低 oracle、改原文件或改变生产政策。

真实 WA 默认只开一个首次导入 job。若唯一失败原因被证明是验收工具故障，且没有越界、生产源码／政策变化或数据替换，最多允许一个新的首次导入重试；分别记录两次及总模型用量，不将失败计时抹去。两次重传是 A02，不用于反复试探首次失败。

出现以下任一情况安全停止依赖工作：

- 隔离失效、默认环境被写入、受保护内容出现无法解释变化。
- 需放宽独立 QA、篡改可信凭据、虚称完整性或绕过删除权限才能推进。
- 当前任务必须使用未实现的新语义算子／格式能力，或关键含义无法由证据确认。
- 冻结后发现真正的生产缺陷，需要再次修改业务策略；记录最小根因，不在本轮边改边重跑。
- 数据 job 预算／无进展条件触发，或总墙钟到达 110 分钟而还未开始收尾。

停止是保存进度的措施，不是通用性成功的证据。系统正确拒绝错误数据和真实 WA 成功导入，必须作为不同结果报告。
