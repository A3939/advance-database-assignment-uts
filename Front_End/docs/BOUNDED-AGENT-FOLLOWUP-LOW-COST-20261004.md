## 4. P0：修复任务相关性误判

### 4.1 已复现问题

当前 task_authority.review 对主表检查键、日期和有界结果字符串，同时接受“任意列名匹配 crash/severity 等词”或“结果值属于已识别类别”。列名信号可以来自与绑定字段无关的列。

下列电商订单在只调用当前纯函数的内存反例中被判为 scoped_for_investigation：

    order_id,purchased_at,order_status,product,crash_note
    sale-001,2026-10-01,paid,Laptop,unrelated placeholder
    sale-002,2026-10-02,shipped,Keyboard,unrelated placeholder

候选绑定是 key=order_id、date=purchased_at、outcome=order_status，purpose=crash_intake。crash_note 不参与绑定，也没有道路安全含义，却足以帮助通过。

该复现没有调用真实模型、容器或数据库；证明的是“进入调查阶段”的误接受，不是官方发布绕过或沙箱逃逸。新增自动化回归必须保留这个精确性质。

### 4.2 替代判定要求

范围判断必须同时考虑用户任务、输入的实际语义线索和所请求操作的必要性。拆开三个结论：

1. 是否允许有限检查这份未知输入。
2. 是否允许围绕具体道路安全目标继续研究或执行某项诊断。
3. 是否满足数据准入、质量和发布条件。

前一结论不得自动授予后一结论。未知来源可以获得有限检查机会；范围不明时保留 metadata/review 状态，不立即授予完整调查预算和 Python 执行资格。

实现要求：

- 无关、未绑定的列名不能单独使判定通过。不能仅把允许关键词替换为更多关键词。
- 日期、编号和普通状态字符串只能证明结构，不足以证明道路安全用途。
- 在语义需要模型帮助时，允许有界、结构化的解释；模型自述不能直接成为执行授权。宿主复核字段、定位、资源关系及可验证条件。
- 明确的用户目标用于限制动作，不是“只要写道路安全就放行”的证明。数据文件、网页、字典、日志中的指令不能改写该目标。
- 合法的未知列名、数字严重程度编码、别名、非政府来源及辅助资料不应被一律拒绝。缺少解释时进入有限调查，而不是根据固定英文词表判死刑。
- 每个文件及所选表分别记录资格、依据和允许用途。一个已通过的主表不能给同包所有附件、工作表或后来下载的资源授予权限。
- 辅助表应有与当前任务有关的实际关系和用途。共享一两个任意键值，不足以授予对整份无关表的任意计算权限。
- 样本只代表有限检查结果。不要把前 64 行通过推广为全文件语义保证。按风险使用有界分层取样、已完成剖析或流式检查；遇到混合内容只允许处理已界定部分，不静默忽略剩余内容。
- 内容哈希、字段绑定、任务目标、操作范围或相关证据改变时，重新审查受影响资格；不得复用失效的范围结论。
- “调查相关”不等于已证明官方身份、使用许可或删除权限。

无需追求无法证明的“识别所有伪装”。应以明确反例、有限权限、累计成本和后续独立 QA 共同约束影响。

### 4.3 生成脚本的动作约束

复用现有 blocker/job/attempt/input 绑定，增加必要的操作目的与输出范围检查。报告只能是诊断结果，不能被当成可信来源或准入收据。

- 一个相关数据文件不能授权用户夹带的通用编程、下载器或与当前目标无关的计算。
- purpose、blocker_id、file_ids 的合法性只是必要条件，还应检查所申请动作是否属于当前卡点允许的处理范围。
- 允许有用的 schema、键、关系、值、坐标和适用变换诊断；不要为了范围审查删掉已验证的合法 Python 能力。
- AST/代码审查用于提前发现问题，不能替代 Docker、挂载、网络、进程和资源隔离。
- scope review 失败时，不得通过换 purpose、换附件或换诊断名字重新获得预算。
- 已启用的数据任务不会因为这轮代码修改而被自动重载、迁移、恢复或重试。

### 5.2 本轮实现范围

研究路径仍必须具有：

- 原始值、日期/计数/坐标未知值语义；不能把 fatal crash 数当死亡人数。
- 失败、取消和重传保护；不能把研究候选完成写成官方导入成功。

本轮先用小型合成输入验证这条衔接，不重复运行 76,657 行 ACT 的真实模型调查。原 ACT 文件及旧候选仅作只读参考；如需截取极小片段作 fixture，创建独立文件并记录父哈希、选择规则和派生哈希，不宣称它是完整官方资源。

## 7. P2：控制调查成本与重复上下文

本轮只做与上述缺陷有关的轻量改进：

- 同输入、同证据、同卡点、同策略下，复用已有已验证诊断结果；原始模型文字不因此获得可信身份。
- 输入、工具/实现依赖、策略或相关证据改变时，使受影响结果失效；不能沿用旧 QA。
- 向模型优先传当前失败、差异摘要及精确读取定位，不每次重复整个历史合同和原文。
- 同一失败的下一次尝试必须有新证据、不同假设或实际修复；没有变化时明确停止原因。
- 不提高模型/tool/correction/wall/compute/storage 上限，不换低配模型制造“节约”。
- 新建测试任务用于隔离和保留失败，不应成为反复获得完整实验额度的理由。实验记录额外汇总本轮总调用与重跑原因。

如修改缓存或复用，补充输入/证据/实现变化后的失效反例。无需为本轮建设新的全局缓存、通用成本平台或新的 Agent 框架。

### 8.4 失败后的收敛规则

失败后先读取同一次失败的日志、最小输入和调用路径；修复后只重跑失败节点及直接影响的相邻测试。不要默认全量重跑。

同一阶段连续出现两次相同原因且无新定位时，先停止扩展实验，输出根因假设、现有证据和下一项最低成本检查。可以继续静态分析和其他独立工作，不要求放弃任务。

需要新增高成本实验才能判断时，说明具体不确定性和拟运行的唯一案例。不能用“再跑一次看看”作为真实模型重跑理由。

### 8.5 L2：稳定后的小型真实 Agent 验收，另行启动

本轮默认不执行。用户明确启动该阶段后，先选一个狭窄问题、一个新隔离任务；保持原模型与 reasoning，预先列出停止条件，不默认跑满原有 120 次调用上限。

优先验证小样本上的范围判断与诊断反馈，或者候选到研究路径的单一衔接，不同时验证 SA 全量、ACT 全量、Studio 真实生成及所有对抗案例。

不得预填最终答案后称为自主成功。保留用户目标、模型实际工具序列、输入哈希、独立预期和真实用量。失败后先离线定位，不自动新建一串任务重跑。

### 8.6 L3：扩大验收，稳定后另行安排

启动前应满足：P0 定点正反例通过；研究路径权限明确；工程提案没有自动写权；L1 无未解释失败；改动清单冻结；累计成本已记录。涉及自主行为的结论还应有适用 L2 证据。

满足条件后提出扩大计划，用户明确启动后再执行，不把“看起来稳定”作为自动开启长实验的授权。

扩大顺序建议：一个未参与开发的合法来源 → 受影响的真实 SA/ACT 路径 → 必要完整回归及浏览器验收。只重跑被修改影响的真实链路，不机械重复上一轮所有实验。需要测试的未知来源不得预先人工制作最终 adapter。

## 9. 环境保护与并行开发

- 开始时只读核对工作区变更、活动进程、源码加载方式、在途任务和当前测试归属。若改动会影响运行 worker 的实现身份，在独立源码环境准备候选。
- 不创建例行 worktree，不从 Git HEAD 重建并遗漏未提交成果；遵守当前 AGENTS.md 的工作区规则。
- 不覆盖另一窗口的 Studio UI、地图或文档修改。按文件和接口明确职责，共享文件有冲突先保留双方差异。
- 本轮默认交付低成本验证后的候选，不凭定点测试结果自动覆盖正常运行环境。必要集成须有适当的受影响验证、空闲检查、备份和回退；无法确认时保留候选并报告具体缺口。

## 10. 交付与验收状态

沿用一份简明后续报告和一个结构化证据索引，不为每次动作生成重复文档。至少包括：

1. P0/P1/P2 逐项状态、实际修改文件和前后身份。
2. 范围审查的新依据、仍可能误判的范围、配对反例。
3. manual_reviewed 现有能力、ACT 衔接缺口和授权来源说明。
4. 工程提案实际走到哪里，哪些步骤仍需维护执行或用户授权。
5. 每次实际测试的节点、环境、通过/失败/跳过、是否真实模型、是否真实来源。
6. 本轮真实模型调用数（默认应为 0）、重跑次数与原因、主要耗时和保留产物。
7. 尚未执行的 L2/L3、正常 Studio/地图等外部范围，以及后续扩大测试的最小计划。

本轮可以完成的结论：相关缺陷已修改，定点逻辑和必要小型集成通过，候选具备进入后续验收的条件。

本轮不能据此宣称：所有卡点自动解决、所有无关请求都能识别、ACT 官方导入成功、所有真实来源通过、正常 Studio 已可写或完整系统回归通过。

最终回复明确给出实现结果、实际小范围测试、未完成项和可打开的证据路径。不要只回复计划，也不要为了得到“全部通过”扩大测试成本或弱化准入规则。
