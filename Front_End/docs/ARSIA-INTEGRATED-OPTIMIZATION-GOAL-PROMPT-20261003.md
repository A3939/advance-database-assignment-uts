## 3. 必须达到的架构结果

### A. 统一候选准入和发布

native、generic、autonomous 可以保留各自识别与解析实现，但必须形成一致的候选身份、必要验证和来源更新政策。这表示对相同风险应用相同政策，不表示每个来源必须同时具备全部可选能力，或所有操作适用最高证据等级。

重点解决 F01–F03：

- 未知 trusted_host 异常必须由宿主正确分类；与直接抛出同类异常行为一致。完整性、环境、配置和系统故障不得交给模型反复改 adapter。
- 手工 confirmed/profile 不能取得已有自主来源的同等身份和删除权限。
- 普通 pinned native 旧输入重传不能把已准入的新版本来源切回旧内容。
- 最终发布统一检查适用的 source/resource identity、准入等级、当前合同与输出身份、fresh QA、兼容性和取消状态；按实际更新操作与能力检查覆盖/移除等证据。完整删除证明不是所有只读分析的前置条件，局部能力受限也不能放开其他更新权限。
- 不削弱不可变 release、事务原子性、防回滚、no_change、未知值和来源独立语义。
- 兼容现有历史数据与固定 adapter，不强迫已验证固定输入重新调用 AI。对遗留结构采用清楚的可信兼容入口，不靠特殊前缀绕过公共门禁。

优先整合现有 contract/publication/registry，不重造一套平行平台或巨大 DSL。

### E. 实施经用户明确要求的兼容性放宽

审查报告第 11 节是本轮新增的必做要求。统一准入应按实际操作需要的证据判断，不能继续把格式差异、附加字段缺字典或可选能力不足一律升级为整包失败。

- **多路径来源绑定：**官网当前字节相等保留为快捷证明；增加代表性输入需要的可信历史收据/版本、官方发布哈希或可重放表示转换等证明方式。上传后原字节仍不可变。仅同表头、同总数、相似样本或填写 URL 不足以证明官方身份。
- **按能力传播阻塞：**区分全局安全/完整性失败、更新操作缺权限、局部指标/关系/地图缺证据。只阻断实际依赖的范围；若仍有独立已验证能力，可按项目政策形成明确受限的发布。原始问题、用户请求的能力、实际达到的能力必须保留，不把受限结果伪装成全部完成。
- **字段与证据分级：**关键计数、键、关联、日期、坐标和更新字段需充分依据；不参与计算的附加字段可原样保存并标语义未解释。合法 PDF/HTML/字典/编码表与标准链可提供证据，不限于 JSON Pointer、固定措辞或单一域名。机械格式探测经无歧义验证后可自动接受。
- **可追踪的 preprocessing：**用原始行去向、变换关系、基数与计数分配验证替代普遍的一行输入一行输出。对代表性验收实际需要的去重、reshape/聚合、关联或坏行隔离，实现受控操作及独立验证；不要求一轮支持任意 ETL，也不能只取消 unsupported 检查。无静默丢行、无任意冲突取值、无通用“坏行低于某比例就忽略”。
- **分开观测与完整覆盖：**可以展示实际记录及观测日期跨度；缺少完整性证明只限制补零、完整期结论或相应删除/覆盖操作。无稳定跨版本键时保存独立候选/版本，不能静默增量覆盖。
- **工程上限可演进：**文件、资源、缓存对象数量阈值根据索引、分块、资源测量及可信预算调整，不能永久作为业务语义限制；仍保留有限内存、展开量、墙钟和模型预算。
- **两类 QA 都要有：**新增能力既有应接入的兼容性正例，也有配对的阻断/限制反例。优先用已有 reader、contract、capabilities、QA 与 registry 完成，不另造复杂政策引擎。

底线保持：不编造事实，不跳过当前候选 QA，不提升未经证明的来源权限，不修改原始输入，不让 adapter 修改自己的验证器，不在取消/失败后错误发布。来源未充分验证时，只有在使用权限与项目政策允许的范围内才能进入明确隔离的候选/研究区；不得污染已验证官方来源或可信 recipe。


F34 的 SQL 恢复演练仅在有合适备份、资源且能完全隔离时实施，不能通过修改现有环境完成。F39 的 Linux/多用户/公网部署列为明确的未验收边界，不扩大成本去实现本轮不需要的平台。

4. **真实测试失败后，先分析根因。** 不盲目重跑同一模型任务，不同时改输入、合同和 QA 后宣称修复。修改候选后的必要 QA 必须重新执行，修复系统后新建测试任务，保留旧失败。
5. **保持频繁但简洁的进展说明。** 说明已确认事实、当前变更、验证结果与未解决项，不反复叙述无变化的轮询。
6. **所有代码修改完成必要检查。** 读取与改动有关的本地 Next 文档；类型/lint/构建等也先判断是否影响现有服务、生成目录或用户修改，必要时在隔离源码快照执行。
7. **没有用户总 token 预算时不替用户编造。** 数据模型实验沿用当前有效的有限模型/工具/墙钟/修订预算，先记录其具体值；不得静默提高或绕过。开发助手消耗与数据处理模型 usage 分开。
8. **外部阻塞不阻止独立工作。** 一个来源登录受限或主库只读检查不可用时，继续能隔离完成的模块；明确哪些结论无法验证，不把文件哈希当数据库内容证明。

## 5. 必须完成的验收

### 5.1 直接回归、安全反例与兼容性正例

覆盖报告复核后仍成立的问题，并至少包括：

- trusted_host 与 adapter 异常的直接/envelope/Session/Bridge 分类一致性；
- 已发布自主来源不能被 generic 同名覆盖；
- native A→新版本 B→旧 A 重传不回退 B；
- 隔离测试误绑定正常实例时在写入前拒绝；
- registry 超过 30 条跨州记录仍能命中；
- 超过 64 个历史 recipe/大量重复运行不会关闭相关来源的候选检索；
- 大文件取消检查不按行新建连接，取消延迟仍受控；
- 中文/emoji 配额、替换净增量、64th run 重试、transfer 故障幂等；
- 真实零月份与未覆盖月份、年份边界一致；
- 目录后端故障可见、失败/取消请求 usage 标未知而非零；
- 父进程退出、输出/解析预算、取消/发布竞争下无错误发布或无主资源遗留；
- 新旧合同/来源键/覆盖/计数/CRS 变化不能因表头相同自动准入。

不得写只重复实现逻辑的测试。按用户批准的第 11 节策略修改过度严格的旧检查时，可以同步修订错误拒绝的 expected，但必须说明依据、使用独立 oracle 并保留安全反例；不得仅删断言或跳过必要门禁刷通过数。
