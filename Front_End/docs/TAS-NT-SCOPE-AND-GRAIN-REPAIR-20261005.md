## 5. A1：范围审查与证据合同

### 5.1 将五类判断分开

下面是语义合同，具体字段名按当前 API 兼容实现：

| 判断 | 可接受的正向结果 | 不能由此推出 |
|---|---|---|
| 可安全检查 | 解析器可在资源限制内读取 | 文件与任务有关 |
| 范围相关性 | 数据粒度、结构、证据和本次目标之间有可核对关系 | 所有字段语义均已解决 |
| 受控执行 | 对固定输入/表/用途开放限定操作 | 任意代码、网络、宿主访问或发布权限 |
| 质量与目标 | 当前产物满足指定目标，或有明确的源数据限制 | 官方身份已验证 |
| 来源及发布 | 符合当前来源、许可、研究授权与发布政策 | 可替换其他数据、覆盖历史或扩大适用版本 |

`other`、未知类别、缺失字段和格式异常优先成为诊断事实。只有有具体无关证据时才判 `out_of_scope`；证据不足可判 `unresolved`，不能把“还未识别”直接等同“无关”。

不要用百分比门槛代替任务相关性：既不允许“已知标签达到 70% 就全部可信”，也不要求“所有值都属于通用词汇表才准执行”。大比例坏值仍应阻止不受限处理，但在用途成立、资源可控时应允许诊断和隔离候选转换。

### 5.2 原始定义可采用真实发布形式

必须直接支持本次原始证据，不让用户或 Agent 先包装一份带 `concept` 的自制 JSON 才能通过：

- ARDD PDF 第 2 页 `Year` 定义及第 3 页 `Road User` 定义。先核对同一 PDF 哈希和当前提取器；上轮字符范围分别为 `[866,909)`、`[326,527)`，不得盲用不同提取版本的偏移。
- TAS JSON 中字段描述、字段类型、renderer 的绑定字段及原始类别列表。
- 同资源的标题/说明/字段表与单字段定义相互补充。

识别依据可以是“字段名＋说明列＋类型/枚举列”的表格关系，不要求出现 `means` 等特定动词。保留正文、页码、表格行列或 JSON Pointer 的精确引用。PDF 提取无法稳定定位时返回明确的提取/定位问题，不把它谎报成字段没有道路相关性。

### 5.3 有限组合证据，而非拼接任意上下文

至少分别验证：

1. **字段关系**：定义确实描述当前选定字段；不能只在同页偶然出现字段名。
2. **资源适用性**：该定义所属的数据集、表、图层、版本或明确派生链适用于当前输入。
3. **用途相关性**：资源与道路安全或本次合理辅助分析的关系成立。

这三项不必出现在同一个极短片段里。允许组合已绑定的同一文档上下文，或通过正式资源标识和版本/派生关系连接的多个文档；每一条边都应可定位。不能把“任意道路网页＋任意同名 Year 字段”组合成授权。

引用对象最少保留：输入哈希、file/table 标识、字段、文档哈希、定位器、提取器版本、引用内容哈希、资源适用关系、支持的具体断言及未解决项。给模型的置信度只可辅助排序，不能代替这些核对。

上传文件中的 `concept`、`approved=true`、`official=true`、文件名及用户声明都不是宿主授权。JSON、PDF 和文本内的提示指令一律视为数据。可信官方文档可以支持字段语义，但“官方域名”不自动证明它适用于当前导出版本。

### 5.4 有限转换授权应允许保留原值

已有可核对的任务相关性时，即使个别类别尚未解释，也可以允许当前输入的保值候选转换、缺失诊断和独立 QA；不要求 Agent 先编造完整严重程度映射。

授权绑定本任务、输入内容、表、用途、允许的读取/派生操作及工作目录。生成脚本在既有沙箱中运行，只读授权输入、只写本轮输出，受 CPU、内存、输出大小和网络规则约束。模型不能授权自己访问其他项目、秘钥、正常数据库或任意外部执行。

原生严重程度标签可以保留；未知类别不能默认映射成非致死、零伤亡或一般事故。是否可解释致死属性、能否作统一类别比较，继续由适用证据、候选映射和独立 QA 判断。

### 5.5 输入与附件角色

零模型复现 TAS JSON 文档的现有路由。若证实 metadata/receipt 被错误送入数据转换路径，修复角色路由而非放行所有 JSON：

- 主数据、字典、图层 metadata、采集 receipt 分别处理。
- 证据附件没有记录集合本来就可能合法，不应单独使主数据的确定性处理失败。
- 声明“证据”不能让实际第二张数据表逃避检查，也不能使证据里的程序指令可执行。
- 用户或模型提示的角色只是候选，宿主依据安全解析和实际内容核验。

## 6. A2：目标表达、能力预检与错误分类

### 6.1 保留全部显式目标

建立向后兼容的目标合同扩展，允许表达当前尚不支持但已明确请求的目标。区分：

- 未请求；
- 已请求且可评估；
- 已请求但实现不支持；
- 已请求但来源证据或源字段不足；
- 已评估满足、带源数据限制满足、未满足。

不得把有限枚举之外的明确目标丢弃后标成 `not_specified`。无法可靠解析的自然语言需求应保留为未解析要求，而非自动完成；本轮 harness 必须通过可信提交入口发送完整结构化目标，不能靠模型改写运行态来补齐。

保留现有 SA 等任务的历史协议含义；不要给旧任务追写新目标或自动恢复。目标、输入或能力语义改变时，收据与缓存需要适当失效，不能沿用旧的 satisfied。

TAS 目标必须覆盖事故粒度、完整记录去向、年度统计、原生严重程度、坐标解释和可用空间结果。空间能力不能只放在自然语言备注中，然后只检查两项旧枚举就报告全部完成。

NT 目标保留死亡人员粒度、年度死亡人数、Road User 分类、合法多人员/同 Crash ID、源未知值语义；不要求源文件没有的地图。

### 6.2 能力预检在付费调用之前

建立或扩展现有预检，输出按目标和数据粒度划分的实现状态：reader、合同、转换、QA、存储、查询、导出/界面、发布策略。

- 有某个 canonical 分支，不等于整个目标链路可用。
- 能力是宿主根据实现及验证材料声明的，不由 Agent 的 confidence 或一段任意脚本宣称支持。
- 已知完整缺口应直接返回工程问题及缺失层级，不让模型阅读完整 SDK 后重新发现。
- 部分能力存在时允许明确的部分工作，原目标仍保留；是否执行部分工作应遵循用户范围，本轮 NT 不进行真实导入。
- 无法确定的数据粒度可把一个明确问题交给 Agent，不能把“尚未确定”误报成“不支持”。

NT C0 必须实证：原请求完整保存，`goal_satisfied` 不为 true，人员相关能力的已实现/未实现项有依据，进入模型前已得到具体结果，传输尝试为 0。

### 6.3 可行动的错误

具体代码名可复用现有规范，但至少区分：工具参数错误、证据提取失败、字段关系不足、资源适用性不足、语义未解决、宿主能力未实现、候选质量失败、发布条件缺失、预算耗尽、无实质进展。

每个 blocker 返回：发生阶段、当前输入/修订身份、已确认事实、最小缺失事实、允许的下一动作、可验证的解决条件、责任方。不要把宿主能力缺口路由成“继续找网页”，也不要把字段证据误拒绝泛化为 `adapter_revision`。

若源数据本身没有某个事实，不向 Agent 要求凭空补出；源限制与实现缺口必须分开。

| 已验证 adapter 查找和适用性验证 | schema/版本发生实质变化后的局部修订 |
| 候选执行、独立 QA、行去向与目标求值 | 根据具体 QA 缺口改进方案或沙箱脚本 |
| 固定工作流推进、预算、缓存与收尾 | 在关键节点决定继续调查、修订、部分结果或工程交接 |

不要要求 Agent 一次次调用固定步骤来“按下一步”；收到有效方案后，coordinator 自主推进至下一项真正需要判断的问题或可信终点。新文件即使命中 adapter，也必须进行适用的 fresh QA。

### 7.2 实质进展与局部阻塞去重

在已有总预算和无进展保护之上，增加可审计的局部阻塞识别，不能简单把当前 40 次门槛调小后结束。

阻塞身份至少关联：阶段、错误类别、目标、输入/字段/资源身份、证据内容及适用关系、相关合同/实现版本。相同文字包装、引用重复读取、JSON 键顺序变化或新增无关文档不产生实质进展。

有用进展包括：新的有效适用证据、已确认的新冲突、绑定修正、实际方案变化、QA 缺口减少或必要能力状态改变。失败本身也可能带来新的诊断信息；不能把所有失败都视为重复。

相同阻塞在相同有效状态下最多允许两次等价重试，随后由宿主返回集中决策包，允许一次有新策略的重规划或工程交接；无新策略时结束本任务调查阶段。这个局部预算不剥夺 Agent 基于新证据继续工作的机会，也不允许靠换措辞不断重置计数。总请求和时间预算继续生效。

### 7.3 按需 SDK 与决策包

保留完整 SDK 的可访问入口和兼容性，但默认只提供当前阶段/粒度相关的合同、例子与工具；给出明确的章节索引、内容版本和按需读取方式。固定执行步骤不需要每轮传回全部说明。

决策包至少包含原目标、未满足项、当前 blocker、已确认事实、相关字段摘要、必要定位引用、已失败策略、剩余预算和允许的行动。原始输入大文件及完整长日志不作为默认模型上下文。

不得为减少上下文而删除决定当前结果的证据、发布限制或原始目标。不要为了达到 token 指标隐藏一次失败调用或修改 SDK 后仍声称版本相同。

- 没有独立事故主表时不能为满足外键生成虚构事故。复用或扩展关系表达来保存 source crash reference，区分已关联父记录和仅有源关系键。

### 14.2 目标、投影、QA 与查询

- 在可信目标合同中支持年度死亡人员计数和原生 Road User 分类，不能只给枚举添加名称而没有求值器。
- Fatality 身份依据资料粒度和字典证据，不从任何 Crash ID 重复度或 Road User 文本猜出。
- `Pedal cyclist` 与字典长标签的字面差异需要适用定义和有解释的别名关系；保留原始值，不做无证据的模糊替换。
- 未知值 `-9` 按字段定义解释，原值保留；不能作为正常年龄、速度或数量。不得捏造日期、坐标和个人身份。
- 年度死亡人数按合格人员记录统计；不同 Crash ID 只用于另一个明确事故指标，不替代死亡人数。
- 单独人员存储、年度筛选、分类查询、导出及可用性元数据贯通；没有支持的 crash/observation 分支不能作为默认兜底。
- 全量 QA 核对行去向、年份、Road User、未知值、重复关系和源子集，不根据产品查询结果反向生成预期。

### 14.3 发布与迁移

仅在独立数据库应用必要的候选迁移并验证旧 crash/observation 最小相关路径。不得迁移正常业务库或 Studio，不默认触发历史 release 回填。

发布元数据应写明全国 BITRE 工作簿派生 NT 子集、死亡人员粒度、覆盖版本及来源身份状态。不得称为 NT 政府全事故库。事务性发布、幂等、复用后 fresh QA、回退及旧 release 可读性都需要定点验收。

### 14.4 后续真实验收门槛

先完成固定 NT 输入的零模型真实转换、独立 QA、隔离存储和查询；冻结源码、独立预期与输入后，才安排一次低预算真实 Agent 验收。不得直接复跑本次 13 请求的失败任务，也不得把 C0 的安全拒绝当作 C1 导入成功。
