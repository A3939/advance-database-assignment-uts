## 1. 用户意图与本轮取舍

用户要求同时满足三个方向：

1. 在后果可控的前提下，尽可能接受合理的道路安全相关数据，包括不完整、格式陌生、非官方来源及相关辅助资料。不要要求数据完美才允许诊断。
2. 常见问题按照明确、可复核的预处理规则直接处理；规则不能覆盖的新问题允许 AI Agent 调查、提出决策和编写隔离脚本。
3. AI 是关键节点的 coordinator 和 problem solver。不要把每个固定动作都交给模型调度，也不要用过窄的动作列表、固定调用次数或机械阶段门槛使 AI 无法解决合理问题。

优化目标不是“模型调用越少越好”，而是：**相同问题少做重复工作，确定性步骤无需模型调度，新的语义问题能及时进入 Agent，成功调查能变成可复用能力。**

本轮以已有低成本候选为基础进行增量开发，不重写整个 pipeline，不引入第二个规划 Agent、后台工程 Agent、向量数据库或通用工作流平台。普通可隔离实现、排错及 L0/L1 验收自主推进；确实缺少事实、授权或无法隔离运行影响时才提出具体问题。

本文对预处理和范围审查的细化，取代旧规格中与其冲突的“一律不允许排除任何行”“所有日期必须有效才有调查资格”等笼统要求。这里允许的是有原始记录、有明确规则、有独立验证和完整去向的处理，不是隐藏错误。官方来源身份、历史替换、删除权限和原始文件保护没有因此放宽。

## 5. 工作包 A：尽量宽容的范围审查

### 5.1 分级允许调查，不要求完美数据

建议用下列结果表达，允许适配已有状态名，但不要改变其区别：

- `inspectable`：格式可安全读取，允许宿主元数据、结构、有限样本和摘要检查。尚未获得生成代码执行资格。
- `relevant_limited`：已有可核对的任务关联，允许指定输入/字段/用途的受限诊断；字段缺失或语义未完全解决不妨碍此级别。
- `relevant`：资源用途和关系已较明确，可进入候选转换。是否可发布继续由质量、身份和授权决定。
- `unresolved`：目前证据不足，有明确的最低成本下一步；保留元数据/定点调查路径。
- `out_of_scope`：存在具体无关证据或请求明显越出目标，说明原因和被拒动作。

样本推断、全量剖析和官方准入分别记录。不能把样本通过写成全文件语义保证；也不能要求全文件每一行都正确后才允许诊断异常。

### 5.2 合理输入的覆盖范围

至少覆盖现有 reader 和算子能安全表达的：事故、车辆/交通单位、人员/伤亡、年度或其他聚合观测、编码字典、天气、道路/区域空间资料、人口/暴露量、交通量、跨版本比较资料，以及为具体道路安全问题提供解释的辅助表。

约束原则：

- 事故主表不统一要求 key/date/outcome 三项全部存在。聚合观测可能没有事故 ID；道路几何可能没有日期；伤亡子表可能没有独立事故严重度。按实际 grain 和用途审查。
- 允许陌生列名、数字编码、非英文标签、缺字段、个别坏值、非政府来源和来源尚未确认的文件进入适当调查。官方身份要求只在其对应环节生效。
- 相关性依据可以来自已验证知识、结构/值分布、可定位文档、实际关联，以及用户提出的具体研究目标。用户目标能解释用途，但不能独自把任意文件变成道路数据。
- 不用“任意列名出现 crash”“模型 confidence 高”“有一两个相同键”单独放行。保留原订单 crash_note 及 severity 改名反例。
- 同一包内每个文件/表独立定范围；主表不能给全部附件授权。文字字段中的指令不能改变任务、预算或权限。
- 若大量值损坏但用途已清楚，可以诊断损坏原因；不要求模型补造字段含义。若完全没有可验证的相关性，保持有限检查而非授予任意 Python。
- 对有明确当前用途的辅助文件，可在没有主表行级 ID 的情况下，以空间区域、时间覆盖、官方区域编码或有证据的聚合关系建立关联。
- 不要求辅助数据 100% 与事故记录匹配；记录匹配、无匹配、多匹配、缺键和覆盖范围。没有事故的天气日期不等于无关数据。
- 多对多或时空关联先报告基数和歧义，不以一次 join 把事故数放大；不能为了匹配偷偷截键、取最近日期或选择第一条。

语义核对不可能识别所有伪装。低后果的检查应宽容，依靠受限工具和隔离降低误接受影响；不可逆或影响正式统计的动作继续要求对应证据与权限。

### 5.3 执行权限按影响授予

将文件资格与动作资格分开。合法动作包括结构检查、缺失/类型/分布剖析、关系诊断、版本值比较、坐标表示诊断、候选预处理及转换。不要继续把所有需求硬塞进四个旧诊断名称。

新增动作应有受控输入、输出协议、任务目的、资源限额和独立验证办法。没有现成算子时，Agent 可提出隔离 Python 候选，不必因名称不在旧枚举里就直接结束调查；宿主只能授权其已支持验证和隔离的动作类别。新增可信 verifier 属维护开发，不能由数据 Agent 自行安装。

诊断数据尽量由宿主投影为相关表和必要字段。诊断无效坐标可以读取原字符串及空值，不得要求所有坐标先成为有限浮点数；检查表达和缺失也不必先证明 CRS。将坐标作为地图位置或进行有语义的转换，仍要求适用坐标依据。

保留无网络隔离、只读输入、独立输出、无凭据/宿主目录/socket、CPU/内存/PID/时间/输出预算。AST 只是预检，不能当隔离本身。可疑指令字段可以作为数据保留，但不赋予执行权；不为每个可疑字符串全盘拒绝合法表。

### 5.4 移除固定行数造成的业务阻断

移除“超过 100,000 行或 32 MiB 就不再有合法检查路径”的逻辑，改为：

1. 使用现有流式 readers；例如以数千行作为批大小，批大小是性能参数，不是数据准入上限。
2. 流式累积行数、字段有效性、空值、有限类别摘要、关系统计及必要内容摘要。不构造整表 list，也不为关联键无限增大内存 set；需要精确去重/关联时使用本轮 staging 索引或有界外部处理。
3. 复用已有同身份的完整 profile，避免 scope、diagnostic、preflight 各自重复读全文件。最终 fresh QA 仍独立读取和验证。
4. 全量扫描不是所有有限诊断的前提。对已经明确相关的表，可以先授权必要字段和目的的隔离诊断，保持 `scan_complete=false` 等限制；只有完成对应检查后才声明完整覆盖。
5. 跟踪实际扫描量、耗时、内存/暂存规模和取消状态。超出当前操作预算时保存已完成范围及原因，不能假称全量通过或自动增加总预算。
6. 分块继续限于当前明确授权的活动任务；不自动恢复历史任务。复用相同输入/reader/策略的扫描进度；压缩文件、多行 CSV 或不可 seek 的 reader 不得伪造字节断点。不能安全续读时，明确记录重读成本或能力限制。
7. 保留压缩膨胀、超宽单元格、损坏文件、路径/符号链接、解码和 reader 资源保护；不能通过移除文件门槛取消这些保护。
8. scope 的调用次数和“范围未确认最多若干次模型调用”不得被每个扫描分块、重复查询机械消耗。重复请求应返回现有状态；有实际语义进展的调查使用同一累计任务预算，不无故重新进入过窄的小门槛。不得以此提高实际配置的总模型/工具/计算额度。

### 5.5 解释证据兼容

复用现有 read_document、JSON/XML/PDF/文本 locator 和源文档哈希，不另造只有自定义 JSON 才能通过的解释系统。

- 来源提供的 CSV 编码表、可读取 PDF 和网页段落能参与相关性与候选规则解释。
- 保存原始文件身份、抽取实现版本、精确位置和适用资源/字段。模型摘要只是候选解释，不变成官方授权。
- 官方认可的外部标准需要保存其与具体来源/字段的关系；不按 `.gov.au` 简单排除，也不泛信任外部站点。
- 扫描 PDF 没有文本或未知格式无法解析时，说明缺的是 reader/OCR 能力；保留有限其他证据路径，不要求用户编造标准 JSON。

## 6. 工作包 B：可执行的预处理政策

### 6.1 三层数据与政策等级

保留三个逻辑层，可复用现有 staging/canonical/metadata，不要求为了命名新建三套数据库：

1. **原始层**：原字节、资源、物理行/表位置和原值不可变。清洗不改写原始文件。
2. **规范化与处置层**：记录规则、有效值/未知值、重复关系、隔离原因及每行去向。
3. **分析层**：按指标和选择范围计算可用数据，附完整性、未知数量和限制。

政策等级：

- **P0 自动规则**：宿主已实现并验收，前提能确定验证，不改变已知事实含义。直接执行，0 模型。
- **P1 证据支持的选择**：存在不同合理解释，Agent 可以定位证据、选择已有算子及参数。宿主验证适用条件后执行；规则和依据进入可复用配方。
- **P2 新诊断/新转换候选**：Agent 可编写隔离脚本。输出仍是候选，必须有相应独立验证；没有 verifier 就进入工程交接，不能用另一段模型文字替代 QA。
- **P3 事实/权限缺口**：缺失事实无法推导、来源身份无证据、需要改变用户目标或发布授权时，保留明确候选和具体缺口。不可由模型自行批准。

本轮对下面低风险规则的实现与隔离执行已有任务授权，不要为每个 null、日期解析或无效坐标反复问用户。会改变统计粒度、推断未知事实、合并版本、抛弃历史或改变研究目标的方案不属于默认低风险规则。

| PP03 | 文本/表头格式 | 可处理 BOM、已有 reader 支持的编码和已审查列别名；值 trim/大小写/Unicode 规范化必须是字段规则 | 不能全局 trim ID、合并类别或改变官方字节身份；列名归一化冲突必须诊断 |
| PP04 | 日期格式可确定 | 按已声明格式或唯一无歧义解释解析；保留来源精度、原值和适用时区 | `01/02/2020` 无依据时不猜日/月；仅有年/月不得补成真实 1 月 1 日 |
| PP05 | 日期缺失/无效 | 标为未知日期，保留事故身份和独立有效字段；时间分析按第 7 节处理 | 不能取上传日、当前日期、相邻行日期或平均日期；有证据可另用独立年份字段 |
| PP06 | 计数缺失 | 保持 null；有效零与未知分开；所有组成项已知且加法语义成立才能求和 | fatal crash 不能推成人数；不以均值、中位数或严重度补伤亡人数 |
| PP07 | 计数格式/非法值 | 已声明数值格式可规范化；负数、非整数或无法解析保留原值并使对应指标无效 | 若会影响其他指标/关系，沿依赖传播；不四舍五入人数取得通过 |
| PP08 | 严重度/分类缺失或新编码 | 已知映射复用；未知编码保留 native 值与 unknown 状态，不阻断已证明的事故记录存在性 | Agent 仅查新增编码；不能默认当 PDO/非致命，也不能把所有未知类别归入某已知类 |
| PP09 | 坐标缺失、非数值、越界 | 保留事故与原坐标，标注地理能力不可用；只从需要有效坐标的结果排除 | 不因缺位置删事故；交换轴、变换 CRS 需证据和既有受验证算子 |
| PP10 | 坐标表示/精度差异 | 原值、数值解释、候选变换分开记录；有依据的转换用于声明的派生结果 | 不通过添加容差、减少小数位或忽略字段证明官方原件身份 |
| PP11 | 完全重复 | 只有同一来源版本、相同完整业务键、相同相关原值/粒度且已有重复处理政策时，选确定代表并记录全部 duplicate_of | 不能仅因整行长得一样就删除两个人/两辆车；已有 collapse 政策优先复用 |
| PP12 | 同键冲突 | 将冲突组标记/隔离，保存全部版本；其他独立记录可继续 | 不任取第一/最后；有明确修订顺序证据才进入 P1；完整快照或关键关系受影响时不能宣称完整 |
| PP13 | 主键缺失 | 使用物理 locator 保存原行，不能把 locator 冒充已知事故 ID；隔离无法可靠建立业务实体的行 | 若存在可验证自然/复合键，可提出 P1；未具备粒度证据不能只按行数算事故 |
| PP14 | 子表孤儿/关系异常 | 保存未匹配子记录和原因，阻断依赖该关系的指标；合法主表及不受影响字段可继续 | 不能凭位置补父键、最近匹配或级联删除；声明完整的子表不再视为完整 |
| PP15 | 辅助表部分覆盖 | 以定义明确的键/时空范围匹配，报告未匹配和多匹配；没有事故的辅助观测仍保留 | 不把未匹配天气补零；不因多对多连接放大事故计数 |
| PP16 | 范围筛选 | 仅执行已明确的年份/地区/研究范围，记录谓词、输入和排除量 | 日期/地区未知不能假称在范围外；保留“无法判断是否属于选择范围”的数量 |
| PP17 | 极端值/不常见值 | 原则上保留并标注；有来源定义或确定物理/类型约束才判非法 | 不默认按 IQR/z-score 删事故；模型不能为了分布好看移除严重事故 |
| PP18 | 单位转换 | 已知原单位、目标单位和关系时用已验收算子转换，保留原值/单位/规则版本 | 猜测单位、聚合人数和事故、把不同时间口径合并进入 P1/P2，缺证据保持未知 |

不默认实现统计插补、模糊实体合并或推测缺失位置。若未来需要，把它们作为独立分析派生产品，显式标记估计和不确定性，不能写回为官方事故事实。本轮应有“不会自动做这些事”的定点反例。

### 6.3 规则执行和 AI 选择协议

预处理计划至少绑定：政策版本、输入身份、资源/表/字段、业务粒度、算子与参数、前置条件、证据引用、预期能力变化、影响统计、执行实现及撤销/重算条件。

程序先完成 profile 和规则匹配。满足 P0 条件即执行；不生成“请 AI 决定是否把这个空字段记为 null”的任务。已有适用 P1 配方经当前依赖复核后也可直接执行。

确需 Agent 时返回具体未决点：

    字段 X 出现新标记 -9；已有配方仅定义空字符串；
    受影响 3 行，事故身份不受影响，死亡人数统计完整性待定；
    已有字典定位 A/B，需确定该标记的含义；
    可返回现有 null-marker 规则的有证据参数，或保持 unknown。

Agent 不能提交任意 SQL、宿主文件路径、任意 dropna/filter 或不受控表达式作为可信规则。支持的筛选/转换使用声明式结构；新 Python 在隔离器执行，QA 必须重读原始输入独立检查其语义和行去向。

未知问题可以保留 unknown 并继续不受影响部分；不能为了 0 模型而把本来能恢复、用户明确需要的能力一律降级。反过来，也不能因为可以调用模型，就为不影响目标的每个空字段展开研究。

## 7. 行去向、指标完整性和独立 QA

### 7.1 行去向账本

对每个实际数据表至少有可核对的互斥主去向：retained、duplicate_of、quarantined、excluded_by_scope。字段质量标记可多个，不计作额外行。格式行/表头/字典由 reader/table plan 单独解释。

基本守恒：

    数据原行数 = retained + duplicate_of + quarantined + excluded_by_scope

一行展开多条规范记录、聚合或查找映射不能套用这个公式声称规范记录数等于原行数；必须另有受支持的 lineage 和 grain 对账。原行守恒与业务实体计数分开。

记录可用 `file_sha256 + table_id + physical_locator` 唯一定位。不要用可能缺失或冲突的业务键作为原始 staging 唯一主键，否则还未建立账本就会丢掉冲突证据。

账本不要求复制整份原文件：优先原文件哈希引用、locator、规则、理由和必要差异。必须保证保留期内原件可取得且哈希可核对。账本由宿主独立复核，不接受 adapter 自报数量就通过。

### 7.2 能力与指标的依赖传播

质量控制到字段、记录、关系和查询选择范围。按依赖计算影响，不能简单以“坏行比例很低”判断安全。

例子：

- 10,000 条已确认唯一事故，50 条无有效坐标：整体事故数 10,000，地图候选 9,950，50 条位置未知。原件保留，不声明地图覆盖全部事故。
- 2 条已确认事故，1 条日期缺失：未限定时间且不存在其他排除时可给 2 条事故；限定年份的结果只包含可证明在该年份的记录，并附 1 条日期未知、无法判断是否属于范围。不能把“未知日期”说成另一个年份或已证明不在选择范围。
- 10 条事故有 1 条死亡人数未知：完整死亡总数为 null；如提供已知行小计，字段必须另名并附 eligible/unknown 数量，不能把部分小计放在原本代表完整总数的字段里。
- 主表声明了全部伤亡人数，子表有孤儿/缺项：不能把子表缺失当零；独立有依据的主表值可保留，但子表重建的明细/分组结果标注相应不完整。

元数据至少能表达：原行数、可识别实体数、主去向数量、各指标有效/未知/无效/排除量、选择范围、完整性状态、依赖问题、政策与证据版本。不能只给一个数据集级 overall_quality 分数。

`available / partial / unknown / unsupported / no_results` 的表达可按现有协议适配，但必须区分“没有记录”“数值为零”“部分记录不可判断”“系统不支持”。前端原有 boolean capability 不能单独表达全部这些语义，应保持旧字段兼容并增加必要详情。

协议示例只用于明确含义，字段可按既有 API 调整：

```json
{
  "policy_version": "preprocessing-v1",
  "raw_rows": 10,
  "disposition": {"retained": 10, "duplicate_of": 0, "quarantined": 0, "excluded_by_scope": 0},
  "metrics": {
    "crash_count": {"value": 10, "status": "available", "population": "identified_crashes"},
    "fatalities": {
      "value": null,
      "status": "partial",
      "known_subtotal": 2,
      "eligible_records": 9,
      "unknown_records": 1,
      "reason_codes": ["SOURCE_VALUE_MISSING"]
    }
  }
}
```

这里 `fatalities.value` 仍是完整总数，不能用 `known_subtotal` 代填。字段级 unknown/invalid 数量应互斥；同一记录的多个问题另外以 issue 列表表达。查询筛选后重新计算适用覆盖，不能把整份来源的未知数量不加说明地当成当前选择范围内的未知量。

### 7.3 QA 与发布规则

1. trusted QA 重新读取原始记录，核对预处理计划前提、处理结果、行去向、关系和指标。不得只读取清洗后的数据验证自己。
2. 不依赖同一个未经独立检查的转换函数同时产生 expected 与 actual；复用可信算子时仍要有独立的行/聚合约束和手算 oracle/反例。
3. sample 通过不能代表 full。不同候选、输入、规则、证据或执行镜像使受影响 gate 失效。
4. 有完整性问题时可形成声明清楚的部分研究结果，但不能宣称完整官方快照、替换历史或删除未出现记录。
5. 官方原始身份与处理结果身份分开：已验证的官方输入经预处理成为可追溯派生结果；保留来源身份，但不得把派生文件哈希声称为官方原件字节。原本身份未验证的数据也不会因清洗而获得官方身份。
6. 对所有记录都不可用、用户要求的核心目标不可满足、关键关联无法界定的情况，保留原件和诊断，不发布空替换来制造成功。确需有限结果须明确其范围和未满足目标。
7. 历史 source/release 的覆盖与删除仍由原更新政策决定。本轮预处理排除不产生历史删除授权。

## 8. 工作包 C：程序执行固定步骤，Agent 负责关键判断

### 8.1 职责分工

| 宿主程序负责 | Agent 负责 |
|---|---|
| 文件身份、结构剖析、已有知识匹配和差异提取 | 全新来源或含义变化的调查策略 |
| 已验收规则选择、确定性预处理和配方编译 | 无法确定的字段、粒度、口径和证据解释 |
| scope/权限/预算和执行器控制 | 提出具体诊断、组合现有能力、生成隔离候选 |
| sample/full、独立 QA、注册和事务发布 | 分析新的失败，选择有证据的修复或替代方案 |
| 状态持久化、取消、幂等、进度展示 | 判断是否确需事实/授权，形成工程交接 |

Agent 可以在任意真正需要判断的节点介入，不只允许“入口一次、失败一次”。但不要求它为固定成功步骤逐个下令，也不为展示进度或确认数据库写入而调用模型。

### 8.2 优先路由

先保留并统一现有 native、generic、recipe、新版本候选和自主路径，避免平行实现两套准入：

    接收并核对输入/目标/权限
      → 确定性 inspect/profile、知识匹配和适用规则
      → 已有可用候选：程序推进
      → 存在未决语义或能力问题：产生 decision packet → Agent
      → Agent 返回候选/诊断方案/明确未决点
      → 宿主校验后继续推进
      → 新问题回到同一 Agent；合法终止条件保留证据并结束

已知输入且依赖未变可以完全零模型。新版本只有部分变化时给 Agent 差异和相关旧知识；不能因为文件哈希不同就从零调查整个发布机构。未知来源允许较完整调查，但输出须沉淀可复用合同/规则/配方。

### 8.3 一个可审查的推进接口

优先给现有 AgentSession 增加或复用一个受控动作，例如 `advance_candidate(expected_revision, stop_at)`；名称仅为建议。它是调用既有动作的程序编排，不是新的 verifier 或发布后门。

该动作在权限允许时依次运行：

    scope/能力/证据预检
    → 预处理计划核对与候选准备
    → sample 执行与 independent sample QA
    → full 执行与 independent full QA
    → 精确版本注册/适用的研究身份处理
    → 已获授权范围内的事务发布

必要条件：

- `expected_revision` 绑定当前输入、合同、代码、预处理计划及相关依赖；任务存在并发编辑或候选变化时拒绝旧动作，不继续用旧 sample gate。
- 只有宿主知道哪些 gate 已完成。Agent 不能提交布尔 `validated=true` 或伪造 receipt 跳过步骤。
- 自动编排每个内部动作仍有独立事件和预算计量；不能因为包装成一个 tool call 就不计内部工具/计算成本。
- 长操作输出进度事件，模型无需轮询“完成了吗”。内部取消点、超时、资源预算继续生效。
- 任一阶段失败，保存实际阶段、输入版本和原始诊断；已完成且同身份的计算可在当前任务中复用，但新 attempt 的 fresh QA 按既有规则重做。
- 没有发布授权可推进到已验证候选并给出清楚结果，不自动切换身份或自签研究授权。
- 注册/发布使用已有锁、事务、取消竞态和 lost-ack 核对。幂等重入不能重复入库或二次 publish。
- 一旦提交已发生，不能因后续 UI/回包失败再让模型重新执行发布；先检查真实事务结果。
- 不在持有长数据库事务或全局锁时等待模型调查。

可参考控制逻辑，实际实现复用现有代码：

```text
advance(candidate_revision):
    check_current_task_authority_and_revision()
    while host_has_deterministic_next_step():
        check_cancel_and_cumulative_budgets()
        execute_existing_step_with_durable_receipt()
        if committed_or_terminal:
            return observed_result
        if new_issue:
            apply_existing_safe_rule_if_applicable()
            if still_requires_judgement:
                return decision_required(current_issue_and_dependencies)
    return exact_current_state
```

这段代码不能以宽泛 `except Exception: call_agent()` 实现。完整性破坏、取消、权限失败和预算耗尽必须停止；普通新语义、数据诊断、可恢复实现问题才进入适当判断或工程交接。

### 8.4 Agent 的输入与返回协议

decision packet 至少包含：

- 原始目标、当前未满足能力、当前允许动作和剩余累计预算；
- 当前 candidate revision、失败阶段、typed issue、具体受影响资源/字段；
- 已确定的事实、未决问题、本次新增差异和依赖标识；
- 必要的统计/最小反例及精确证据读取定位；
- 已尝试的策略及结果摘要，哪些内容可复用；
- 可直接调用的已有算子/诊断能力，以及宿主不能支持的能力。

Agent 可返回：已有规则的参数化选择、合同/adapter/预处理候选修改、绑定假设的隔离诊断计划、需要新证据的定点获取动作、工程提案、具体用户问题或明确无法完成的原因。

原始行和整篇历史不默认进入上下文。确有必要可通过受控分页读取相关字段/证据，保留精确引用；不能为省 token 删除对当前判断关键的反例或冲突。宿主状态和来源文字的信任等级持续区分。

为每次介入保存稳定 reason code，例如 `NEW_SOURCE_SEMANTICS`、`SCHEMA_OR_CODE_DRIFT`、`AMBIGUOUS_TRANSFORM`、`NEW_QA_FAILURE`、`ENGINEERING_GAP`；不要将普通进度更新伪装成新语义问题。Agent 的建议至少带 `base_revision`、候选动作、理由、引用/依赖和预期受影响能力，宿主返回 `accepted_for_execution`、`decision_required` 或精确拒绝原因。`accepted_for_execution` 只表示可执行候选，不表示已通过 QA 或发布。

### 8.5 合理继续与无进展收敛

- 不用固定“最多 2 次介入”限制正常问题求解；继续使用当前配置的累计任务预算和风险约束。
- 每次重试应说明新的证据、实质不同假设、实际修复或已确认的暂时故障条件。更换自然语言措辞、文件名、purpose、空白代码或新 job 不能算进展或续额。
- 相同失败和相同依赖下，优先返回已有诊断；没有新信息时停止重复执行，保留下一步所需条件。
- 允许新证据使已停止的策略在明确授权的活动任务中重新评估；不能把负缓存变成永久封锁合理数据。
- 宿主暂时性故障用既有有界重试机制；不要为每次网络/SQL 瞬时问题调用 AI。实现缺陷生成最小复现和工程交接，不让数据 Agent 反复搜索来源网页。
- 保持一个数据任务的既有 Agent/session 和累计预算。不通过另起 Agent、复制任务或换 engine 绕过限制。

### 8.6 实施边界

同时检查 codex runtime 指令、tool schema、SDK 和 workflow state。不能只新增推进函数，而仍在 prompt 里要求模型手动走全部旧步骤。保留旧工具作为需要时的精确诊断入口，正常成功路径优先连续推进。

新行为只应用于本轮新建/明确选择新政策的任务。旧 session/checkpoint 不自动迁移、重载或继续。需要兼容旧合同和旧数据时，显式识别版本，不能读取旧状态时偷偷补新权限。

## 9. 工作包 D：正确复用知识、诊断与失败证据

### 9.1 复用层级

区分并记录：

1. 原件/公开证据按内容哈希去重：减少下载与磁盘复制。
2. 结构/profile/字段语义证据：依赖当前输入、reader、定位和适用范围。
3. 纯诊断计算：依赖精确投影、相关证据、算法和环境。
4. 已验收预处理与 adapter 配方：复用语义和执行计划，仍 fresh QA。
5. 发布结果：继续现有 no_change/事务规则，不与诊断缓存混同。

### 9.2 依赖必须具体

修正“加入无关文档就使 blocker/diagnostic 失效”的情况。收集实际读取/引用的文档、locator、字段、实现和父范围依据；对任意候选脚本无法证明其只读取部分输入时，保守绑定整个允许输入。

相关文档内容改变时，先使对应引用失效并重新定位/验证，不能仅凭 locator 字符串相同继续使用。输入字节改变使依赖其内容的计算失效；字段语义可重新绑定后复用，不等于复用旧运行结果。

失败身份应足以区分问题，但不要把每次 UI 读取、新增无关文档或时间戳当作新的问题。AST hash 可帮助识别代码等价，不足以证明语义进展。

### 9.3 跨任务复用与权限分开

目前候选诊断缓存绑定 job/attempt，主要解决当前尝试内重复。本轮至少实现一种可核对的跨任务纯诊断复用：

- 复用的计算对象按内容、相关依赖、策略/算法、输出协议和镜像身份寻址；当前任务仍重新获得自己的 scope 和执行/读取授权。
- 不从缓存继承旧 job 的授权、发布收据、目标满足状态或 QA。
- 复用前核对结果文件完整性与适用条件；有新任务的复用收据，指向旧计算来源。
- 缓存隔离在本地实例/授权范围内，不能跨不相关用户或任意工作区读旧数据。
- 优先沿用现有 knowledge/cache 文件和索引，不建设新的全局服务；并发写采用现有可用的原子写/锁机制。
- 无法在现有边界内安全复用的诊断允许明确标记 task-local；不能以此把所有诊断都继续绑定 attempt 而声称跨任务成本问题已解决。

QA 报告即使内容相同也不能用这种诊断缓存跳过新任务 fresh QA。缓存命中统计和模型调用统计分别记录。

## 10. 工作包 E：存储、查询、展示与研究路径

### 10.1 未知日期必须真正存得下、查得对

已知当前投影要求可解析日期，canonical_crash.year 为 NOT NULL，query 使用 year/month 过滤。执行者必须贯通修改，不能只让 scope 返回通过。

本轮目标：在新政策和独立测试数据库中，保留具有可靠事故身份但日期未知的规范记录；日期精度/状态明确，无伪造年份。未限定时间的计数和限定时间的计数按第 7 节返回覆盖信息。

可对新建隔离 schema/版本做最小扩展，并提供可审查的迁移方案或脚本及隔离演练。**不得自动应用到正常业务库或 Studio。** 正常旧 schema 仍应可读；需要新存储能力的候选在写入前得到准确的 capability preflight/维护提示，而非中途 SQL 崩溃或静默丢行。

若为兼容采用等价的独立表示，必须证明未知日期记录仍能参加适用的整体查询且不会重复计数。只把记录放在无人可见的 quarantine 而宣称“缺日期不影响事故总数”不满足要求。

### 10.2 结果和界面

沿用现有 source identity、publication_status、capability_limits 和 research_context，最小扩展质量/预处理元数据。兼容旧 release，旧结果没有新字段时显示“未提供该项报告”，不能当作缺失为零或质量完全通过。

至少通过真实查询/API 合同及直接相关 UI 组件验证：

- 原始数量、可用数量、重复/隔离/范围排除数量；
- 时间、位置、伤亡等受影响能力和未知量；
- 采用了哪些规则、是否有 Agent 新判断及可追溯证据；
- 来源身份、派生结果身份、原目标是否满足；
- 部分结果与完整结果的区别。

修改以 Imports 结果详情及现有共享来源元数据传播为主，不重做 Studio 布局或地图。Ask AI/Studio/导出不能在收到 partial 元数据后重新包装成完整事实；若消费端尚不能呈现某项语义，诚实限制对应输出并记录缺口。

### 10.3 ACT 原件与研究能力

原件身份参考：16,637,960 bytes，SHA256：

    950eb319cc566d375f7fbe993760cbc8245f4f1d51b93b5a0baa720eb4cebb41

历史观察：76,657 条唯一 CRASH_ID，Fatal 105、Injury 6,576、Property damage only 69,976。它们是对用户文件的观察，不是官方认证，也不是死亡/伤亡人数。执行时核对原件，不从此表直接填入测试实际值。

先用小 fixture 完成研究路径和预处理逻辑。随后可在同一授权的隔离开发范围内进行**一次零模型、只读原件的完整本地转换及独立对账**，目的是补齐原件实际转换，不重跑官方来源调查、不下载替代样本、不调用模型。其产物留在本轮独立候选/测试库。

这一步不是默认扩大成全部真实来源验收：只测 ACT 原件、适用已实现规则和非空间研究结果；失败先最小化到 fixture，修复后只复验受影响部分。不要为每次局部修改都重新完整处理原件。

若官方身份仍不成立：

- 研究授权继续来自现有受控入口，复用有效收据；模型 confirmed 和上传 JSON 不能自授权。
- 测试可以通过明确的测试用户提交真实入口建立隔离研究授权，必须标为隔离测试，不能复用成正常环境权限。
- 保留原目标及 target_satisfied=false；官方注册为 false。
- 坐标表示诊断不等于可信地图能力；未完成对应证据与验证时保留原值和限制。
- 报告原件转换、研究发布、官方绑定三个独立状态。任何一项未执行或未通过都明确标注。

### 10.4 SA 与暂缓范围

保留两个独立官方版本以及禁止直接跨版本相加的政策。新版本先确定性比较和复用，只有未解释变化才交给 Agent。

本轮不以证明 SA 逐事故映射为前置条件，不新增全州调查，不重跑完整 SA 版本对模型任务。不同版本 ID 的截断、按数量相等推定对应、自动“最新”切换或删除旧事故均不属于默认预处理。

## 11. 实现落点与避免重复建设

具体模块可以调整，但先形成简短映射并以实际代码为准：

| 规则政策与行去向 | canonical/generic、现有 transform/collapse/exclusion 结构、trusted_qa；必要时新增小型政策模块 |
| 固定步骤推进 | AgentSession/worker/adapter_reuse 共用的编排函数；保留现有执行及发布 gate |
| 关键节点 Agent | repair_context、codex_bridge/runtime、tool schema、SDK、workflow state |

## 12. 分阶段实施顺序

### D0：只读基线与最小执行计划

核对源码/候选哈希、当前任务状态和测试隔离能力；列出实际缺口、会修改的职责和初始测试节点。保存基线，不修改正常环境。无需为了写一份计划而再次询问已明确的技术选择。

### D1：范围、规则和数据表达

先完成范围分级/流式检查、原行身份和规则协议；再实现缺失日期/计数/坐标、重复冲突及关系传播的最小纵向链。不要先放宽 gate 而把 loader/query 不兼容留到最后。

### D2：程序推进与 Agent 交接

使用 D1 的实际候选和失败类型，实现固定动作推进、decision packet、精确版本门禁、无进展收敛及兼容旧任务。用受控 Agent 替身验证新的协调协议，证明程序接管了步骤。

### D3：复用、研究交付和必要展示

完成依赖准确的诊断复用、研究身份和 partial 元数据传播。执行必要 L1 和一次零模型 ACT 原件对账，形成可审查候选。

### D4：默认本轮结束点

交付候选、证据、成本和下一项最小真实 Agent 验收方案。**不自动启动 L2/L3，不自动集成正常环境。** 因本轮默认不使用真实模型，不能宣称真实 Agent 已达到设计效果。

## 13. 低成本验收方案

### 13.1 默认边界与成本记录

默认仅 L0、必要 L1 和第 10.3 节一次零模型 ACT 转换；ARSIA 导入/分析真实模型调用 0。开发 Codex 自身用量与 ARSIA runtime 用量分开，不写“整个开发不消耗模型”。

不运行全部 Python suite、全部数据库模块、整站 E2E、完整 SA/ACT 模型任务。对每个实际改动选择能揭示问题的测试，不为改文案或字段重命名创建镜像式测试。

执行前记录本批节点、要验证的风险、是否网络/模型、隔离对象和范围。失败后先读同一失败证据，修复后重跑失败节点和直接相关的邻接节点；同原因无新定位时先缩小复现，不升级昂贵实验。

### 13.2 L0：逻辑与协议定点用例

以下是风险覆盖矩阵，不要求每行独立启动一次 pytest；优先参数化和复用 fixture，按行为断言，不用待测函数自己生成 expected。

| 编号 | 小范围用例 | 必须证明 |
|---|---|---|
| S01 | 原订单 crash_note + severity 改名反例 | 可以安全检查，但不能借列名取得无关脚本权限 |
| S02 | 陌生字段/数字编码/非英文道路资料 | 可定位依据后取得适用调查权限，不要求全部字段已完美 |
| S03 | 缺日期事故、年度聚合、无日期空间/字典资料 | 按实际 grain 授权，不统一要求事故三字段 |
| S04 | 100,001 行及超过 32 MiB 的合法流式 fixture | 不触发原固定拒绝；内存不随整表 list 增长，取消有效 |
| S05 | 看似相关开头后混合内容、多表附件和字段内指令 | 有限资格不扩展整包；混合/无关部分有记录，不静默忽略 |
| S06 | 天气包含无事故日、合法时空辅助关系、多对多反例 | 部分匹配可用；多匹配不膨胀事故数 |

| S08 | 已支持 CSV/PDF/文本 locator 及错误引用 | 不依赖自定义 JSON；伪定位、错资源和修改证据失败 |
| P01 | null/0/N/A/未知标记、字符串键前导零 | 规则按字段生效，零/ID/类别不被全局清洗破坏 |
| P02 | 可确定日期、日月歧义、缺日期、仅年/月 | 日期精度和 unknown 正确，无猜测或伪造日期 |
| P03 | 2 条事故 1 条无日期；时间筛选及未限定时间查询 | 总体和选择范围语义正确，未知归属明确 |
| P04 | 计数缺失/非法；Fatal 标签；新严重度编码 | 未知不是零；事故不是人数；未知类别不强行归类 |
| P05 | 少量坐标缺失、越界和有依据的转换 | 保留事故，限制位置能力，不改变官方身份 |
| P06 | 合法同键同值重复、同键冲突、不同人物同值 | 只去证明的重复；完整 lineage，无任意保留第一条 |
| P07 | 缺键/孤儿/完整子表不完整、显式范围筛选 | 原行全部有去向；不伪造键、不丢关联、不宣称完整 |
| P08 | 离群值、模糊 ID、统计插补请求 | 不默认删除或将推测写成事实，可进入合适候选/限制 |
| A01 | 已有完整候选连续推进到发布 | 0 模型；sample/full/QA/注册/事务顺序和证据真实 |
| A02 | 新语义卡点→受控 Agent 返回修复→继续 | 只在关键点调用替身；固定成功步骤无需再次询问模型 |
| A03 | 候选在 sample 后变化、旧 revision 重入 | 原 gate 失效，旧候选不发布 |
| A04 | 取消/预算/完整性失败、未知授权 | 正确停止，不自动另开 Agent/任务续额 |
| A05 | 发布失败、lost-ack、幂等重入 | 查真实提交状态，不重复发布；可调查问题返回正确节点 |
| A06 | 相同失败换措辞/空白代码；真正新增证据 | 前者复用/收敛，后者可继续，预算不重置 |

S04 只需两个必要边界 fixture：窄表覆盖行数、适度宽表覆盖字节数，流式生成并限量保留。不为了测试“无限大”创建超大文件。内存断言使用可信观察/实现审查和稳定上界，不依赖脆弱的精确毫秒或 RSS 常数。

### 13.3 L1：少量真实隔离执行

按本轮实际修改选最少必要案例，可把多项断言放在一个小会话内；现有 harness 的实例隔离要求优先，不能为了少建库破坏它。

- 小型 parser→预处理→独立 QA→真实 SQL→查询链：覆盖未知日期、缺计数和位置、行去向/partial 元数据，以及拒绝候选不改 release。
- 一个程序推进真实链：模型采用明确替身；验证内部步骤实际执行和审计预算，不只 mock 所有 gate 后断言状态名。
- 执行器边界发生变化时，一个合法小诊断和一个越权反例，保持真实 Docker 隔离。镜像内代码没变不重复构建，变了则用本轮独立镜像并固定实际 hash。
- 诊断跨任务复用：第二个任务取得自己的权限，命中同一计算；改变相关依赖再证明失效。
- ACT 原件一次零模型完整对账，单列为真实用户输入的确定性验证，不算真实官方准入或模型自主验收。
- 只对改动的前端类型/组件运行定点检查；若改动确实影响打包再做独立输出构建。真实浏览器不能安全隔离时标 not_run，留给明确维护窗口。

### 13.4 L2：之后单独启动的一个真实 Agent 案例

本轮把最小命令/配置和停止条件准备好，不执行。

选择一个包含真实未决点的小型案例，例如有可定位字典的新编码和一个缺日期记录。让真实 Agent 自己解释/提出方案，程序自动完成后续验证；不要开发助手预填最终映射后称为自主成功。

记录每次模型调用的触发原因、阶段、新信息、输入/输出/cached token、工具动作和总耗时。期望关键节点介入有效，不人为承诺固定 1 次或 2 次一定解决。再次提交相同输入应验证确定性复用和 fresh QA；这不意味着要重新启动全套历史模型测试。

失败先用本次日志和最小 fixture 定位，不在没有新定位时重跑真实模型。保留失败，不把重跑次数累计成新数据源覆盖。

### 13.5 L3：稳定后再扩大

只在另行启动后，选择未参与开发的合法来源、受影响的 SA 更新或其他真实链路，以及必要完整回归/浏览器验收。沿用已有证据，明确哪些旧结果需重测，不能笼统重跑所有历史任务。

## 14. 成本和效果如何衡量

至少按以下类别记录，不只报一个总 token：

- 已知输入、兼容新版本、语义变化、全新来源、预处理异常、工程故障。
- 模型调用触发原因；是否产生新证据、候选、修复或明确限制。
- 确定性规则命中、adapter 命中、profile/诊断复用与失效原因。
- 各固定步骤的本地时间/扫描量、模型时间、已知 token、未知 usage 数量。
- 输入 tokens 与其中 cached 部分分别列出，不能重复相加或当作免费；开发助手用量另列。
- 实际测试节点、重跑原因和不同原始输入数量，避免多次同一任务被计成广泛覆盖。

默认验收预期：已知且兼容的输入 0 模型；常见已审查预处理 0 模型；同一未变失败不重复完整调查；Agent 返回候选后固定步骤自动完成。真实来源节约比例需 L2/L3 后实测，不能依据 mock 调用数量宣布节约了某个百分比。

不为了成本更换当前模型/推理档位、不提高总预算、不删必要 QA。先减少不必要的调用、无关上下文和重复计算。

6. **成本记录**：本轮 ARSIA 模型调用实际值、重跑、缓存/规则命中、下一项唯一 L2 计划。
7. **未来集成与回退说明**：正常环境仍未集成；必要源码/数据库兼容变更、停机或迁移要求、备份/逐文件回退办法，不自动执行数据库恢复或正常 Studio 迁移。

本轮实现完成要求：

- 合理数据的诊断不再依赖日期/坐标全部正确或小于固定行数。
- 无关数据反例与执行隔离仍成立，局部授权不扩散到整个附件包。
- 默认预处理真实执行、原件不变、每行可追踪，查询不会把部分/未知当完整/零。
- 已知候选的固定阶段由程序真实推进；新问题有可用的 Agent 交接接口与受控替身验收。
- 纯诊断至少有一种跨任务安全复用，相关变化正确失效，fresh QA 未被缓存替代。
- 原始 ACT 的实际确定性转换与限制单列，未验证官方身份不包装成官方成功。
- 正常数据库、Studio、release、历史任务和其他窗口修改没有被改变。

不能据此声称：所有合理数据都已兼容、所有伪装都能识别、真实 Agent 自主流程已通过、ACT 官方导入成功、SA 逐事故映射成立、全部来源/平台已回归、正常环境已集成。

遇到新发现导致某项无法在本轮安全完成时，保留已完成部分、最小失败证据、实际根因和下一步；不得通过把 required 改成 optional 或隐藏不支持来制造“全部完成”。正常独立工作继续推进，不因一个事实缺口放弃其他可完成项。
