## 防止版本混入

1. 只从当前 ARSIA 向 Front_End 同步经过复核的内容。不要从旧候选、旧 Front_End 或 Git HEAD 重新拼装。
2. 正常使用只打开 3100；不重启旧 3101、3132、3133 等预览。构建检查可以使用独立输出，但不启动另一套正常服务。
3. 当前数据身份必须通过 URL / catalog / release 绑定。旧 official-v1 链接仍属于历史快照，不可把数据版本切换误认为更新应用。
4. 旧版本和失败证据保留供审计、回退，不作为当前任务指令。新的任务不会自动重跑历史导入或模型验收。
5. 后续修改以此为基线，记录差异、完成针对性验收、更新同步清单。发现并发修改先比较，不能覆盖未知变动。

## 同步边界

同步源码、pipeline 实现与知识资产、测试、文档、依赖清单、公开聚合快照和边界；不复制 `.env*`、`.git`、`node_modules`、Python 虚拟环境、原始数据、数据库/卷、用户上传、Studio 研究、运行日志、历史候选、Codex 二进制或旧构建。

Front_End 不单独配置或运行正常服务。其原有构建和过时展示版说明保留在本次同步备份中；同步后构建仅验证当前代码，不复制 ARSIA 私有运行配置。
