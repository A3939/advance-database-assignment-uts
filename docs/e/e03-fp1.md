# E03 — FP1 SQL and deployment

Owner: Role E / Aditya. PostgreSQL repair and validation: Role B / Peixian.

`e.fp1(jsonb) -> text` returns SHA-256 of PostgreSQL's canonical JSONB text,
encoded as UTF-8. B supplies `FrozenManifest.fingerprint_input()`, which
excludes provenance and runtime values. The result is 64 lowercase hex digits.

Apply A's migrations 001–011, then `sql/e/fp1.sql` as the database owner.
The function uses PostgreSQL 16's built-in `sha256(bytea)`; no extension is
needed. It grants `arsia_loader` schema USAGE and function EXECUTE, but no
schema CREATE or PUBLIC execution. A03 table permissions stay unchanged.

Register it with B:

```python
FP1Operation("e", "fp1", "e03-fp1-v1.1", 160015, "sql/e/fp1.sql")
```

This pin matches the tested PostgreSQL 16.15 image. Record the actual server
version, UTF8 server/client encodings and UTC timezone when deploying.
Include the SQL's actual path and SHA256 in the `fp1` inventory component.
B checks the file hash and SQL signature; the file hash alone does not prove
which SQL is deployed. Keep the deployment log too.

FP1 never commits, rolls back or closes the caller's connection.
See [reproduction and results](e03-e06-review.md).
